# FaultPilot Java 故障排查与监控助手需求规格说明书

版本：V1.6
日期：2026-06-01
项目定位：面向通用 Java 项目的开源 AIOps 排障助手

> 对应统一规格：`docs/specification.md` V1.6。发生冲突时以统一规格为准。

## 1. 项目背景

Java 项目的线上排障通常涉及应用日志、接口耗时、JVM 状态、数据库慢 SQL、服务器指标、发布记录和历史处理经验。不同项目的技术框架、日志存储方式和监控成熟度差异较大，信息分散，问题定位依赖个人经验。

本项目建设一个名为 FaultPilot 的 AI 故障排查与监控助手，可部署到独立服务器或容器平台。任何 Java 项目只要遵守统一接入协议，就可以按需提供日志、指标、慢 SQL 和发布事件。助手负责读取授权数据、关联证据并生成结构化诊断报告。

助手的定位是“只读分析与决策辅助”，不是自动运维平台。默认不自动执行 SQL、不修改配置、不重启服务、不回滚版本。

对于 Spring Boot 项目，系统后续提供一个可选的轻量 Starter，用于降低接入成本。Starter 仅负责异步采集、脱敏和上报事件，不包含大模型，不执行根因分析，不把完整助手嵌入业务进程。助手仍然独立部署。

## 2. 建设目标

### 2.1 业务目标

- 为不同类型的 Java 项目提供统一的排障入口。
- 降低研发人员检索日志、比对指标和整理时间线的耗时。
- 让常见问题能够基于证据形成初步判断。
- 沉淀可复用的接入规范、数据适配器和历史案例。
- 以通用开源项目形式发布到 GitHub，不绑定任何公司内部系统。

### 2.2 量化目标

- 用户提交诊断请求后，60 秒内生成初步报告。
- 对预置演示案例，报告必须展示异常时间线、根因候选、关联证据和处理建议。
- 默认限制单次日志查询跨度和最大返回条数，避免拖慢业务系统。
- 任何生产数据源均使用独立只读账号，不允许 AI 自由生成和执行 SQL。
- 未配置生产数据源和模型 Key 时，使用 Mock 模式也可以运行完整演示。

## 3. 适用范围

### 3.1 支持的 Java 项目类型

| 项目类型 | 接入方式 |
| --- | --- |
| Spring Boot Web 服务 | Actuator、Micrometer、日志采集器、可选接入 Starter |
| Spring MVC 或传统 Servlet 应用 | OpenTelemetry Java Agent、JMX Exporter、日志采集器 |
| Dubbo、gRPC 或微服务应用 | OpenTelemetry Java Agent、框架指标、日志采集器 |
| 定时任务和批处理服务 | JVM 指标、任务事件、应用日志、可选业务指标 |
| 普通 JVM 后台服务 | JMX Exporter、OpenTelemetry Java Agent、日志采集器 |

### 3.2 能力边界

助手无法在完全没有可观测数据的情况下自动发现问题。项目接入后能够分析到什么程度，取决于项目提供的数据：

| 已接入数据 | 可分析能力 |
| --- | --- |
| 仅异常日志 | 高频异常、堆栈聚类、发生时间和模块定位 |
| 日志 + JVM 和服务器指标 | 增加 CPU、内存、GC、磁盘等关联分析 |
| 日志 + 接口指标 | 增加慢接口、错误率和流量变化分析 |
| 日志 + 指标 + 慢 SQL | 增加接口变慢与 SQL 性能问题关联分析 |
| 日志 + 指标 + 变更事件 | 增加发布、配置修改与故障时间线关联分析 |

### 3.3 两类接入路径

| 路径 | 是否依赖 Starter | 适用情况 |
| --- | --- | --- |
| 外部数据源接入 | 否 | 已有 Prometheus、Loki、Elasticsearch、数据库日志表或 OpenTelemetry |
| Starter 辅助接入 | 可选 | Spring Boot 项目希望通过少量配置快速上报慢接口、异常摘要和生命周期事件 |

Starter 不是接入助手的前置条件。任何 Java 项目均可仅通过外部数据源、Java Agent、日志采集器或 Webhook 接入。

## 4. 接入等级

### 4.1 L1 基础接入

适合快速试用和低改造成本场景。

- 注册唯一 `projectId` 和环境。
- 提供日志来源：文件、数据库日志表、Loki 或 Elasticsearch 至少一种。
- 提供只读访问权限。
- 配置查询时间范围、最大条数和脱敏规则。

L1 支持异常检索、日志聚类、时间线和基础 AI 建议。

### 4.2 L2 标准接入

适合持续监控和告警触发排障。

- 满足 L1。
- 提供 JVM 和服务器指标。
- Web 项目提供接口耗时、QPS 和错误率指标。
- CI/CD 或运维平台推送发布、回滚和配置变更事件。
- 推荐配置链路标识，例如 `traceId`。

L2 支持慢接口、资源异常、发布关联和自动告警诊断。

### 4.3 L3 增强接入

适合需要精确定位性能问题的生产系统。

- 满足 L2。
- 提供参数化后的慢 SQL 数据。
- 接入完整链路追踪或 OpenTelemetry Trace。
- 接入历史故障案例库。
- 可选接入业务指标，例如订单失败率、任务积压量和消息消费延迟。

L3 支持跨数据源证据关联和更精确的根因候选。

## 7. Spring Boot Starter 需求

### 7.1 定位

Starter 是一个可选的轻量接入 SDK。它运行在 Spring Boot 业务进程中，但完整 AI 助手仍然独立部署。Starter 的目标是减少接入配置，不是替代 Prometheus、日志平台或 OpenTelemetry。

### 7.2 Starter 应提供的能力

- 自动读取 `projectId`、环境、应用版本和实例标识。
- 生成或透传 `traceId`。
- 记录接口耗时、状态码和异常摘要。
- 仅对超过阈值的慢接口生成事件。
- 可选采集参数化后的慢 SQL 耗时。
- 推送应用启动、停止和健康状态事件。
- 在本地完成脱敏、截断和 SQL 参数化。
- 使用后台线程异步批量推送事件。
- 上报失败时有限缓存或丢弃，不影响业务请求。

### 7.3 Starter 明确不做的事情

- 不调用大模型。
- 不分析根因。
- 不主动查询业务数据库。
- 不执行 SQL、Shell 命令、重启或回滚。
- 不阻塞业务线程等待助手响应。
- 不无限缓存事件。

### 7.4 Starter 验收要求

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| S-01 | 可选启用 | 未引入 Starter 的项目仍可通过其他方式接入 |
| S-02 | 故障隔离 | 助手不可用时业务请求仍然正常完成 |
| S-03 | 异步推送 | 上报不在业务请求线程中执行 |
| S-04 | 缓冲限制 | 本地缓冲有明确上限，达到上限后按策略丢弃 |
| S-05 | 脱敏 | Token、密码和 SQL 参数不发送到助手 |

## 8. 核心使用场景

### 8.1 异常排查

```text
项目：order-service
环境：production
时间范围：最近 2 小时
问题：为什么订单创建接口频繁失败？
```

助手输出失败次数、时间分布、高频异常、关联模块、链路标识、根因候选和排查建议。

### 8.2 慢接口排查

监控平台检测到接口 P95 持续高于阈值后，将告警推送给助手。助手查询接口指标、JVM、服务器状态、应用日志、慢 SQL 和发布记录，判断问题更接近流量突增、GC、连接池耗尽、依赖服务变慢还是 SQL 性能下降。

### 8.3 慢 SQL 排查

助手读取经过脱敏和参数化处理的慢 SQL 记录，统计 SQL 模板的出现次数、平均耗时、最大耗时和首次出现时间，并结合接口时间线生成优化建议。助手不执行 `EXPLAIN`、`CREATE INDEX` 或其他 SQL。

### 8.4 定时任务排查

批处理或定时任务项目推送任务开始、完成和失败事件。助手结合任务日志、JVM 指标和依赖状态，判断失败集中于数据异常、外部依赖、资源不足还是执行超时。

## 9. 非功能需求

### 9.1 安全

- 数据源账号必须最小权限，只允许查询指定视图、日志索引或指标接口。
- 凭据仅通过环境变量或密钥管理系统注入。
- 发送给模型前过滤密码、Token、手机号、身份证号、邮箱和业务敏感参数。
- 诊断过程必须记录审计日志。
- 默认不允许助手使用 SSH，不允许执行 Shell 命令。
- Starter Token 仅用于写入事件，不授予查询其他项目数据的权限。

### 9.2 性能

- 日志查询必须包含时间范围，并设置最大查询跨度和最大条数。
- 数据库日志表必须为时间字段建立索引。
- 优先查询只读副本，避免高峰期执行模糊搜索和全表扫描。
- 大模型仅接收摘要和代表性样本，不接收全部原始日志。
- Starter 必须异步上报，网络请求、重试和序列化不得阻塞业务请求线程。
- Starter 的内存缓冲必须有固定上限，助手不可用时不得无限增长。

### 9.3 可扩展性

- 数据源通过 SPI 或适配器扩展：JDBC、Prometheus、Loki、Elasticsearch、OpenTelemetry、Webhook。
- 不同项目使用统一 YAML 配置或注册 API。
- 诊断流程与具体框架、数据库、日志平台和模型供应商解耦。

## 11. 不在首期范围内

- 自动执行数据库语句。
- 自动重启服务、修改配置或回滚版本。
- 直接登录业务服务器。
- 读取未授权业务表。
- 替代现有监控平台、日志平台和链路追踪平台。
- 在 MVP 阶段强制要求业务项目引入 Starter。

## 12. 开源要求

- 仓库使用虚构项目名、虚构日志和本地 Mock 数据。

- 提供 `.env.example` 和脱敏后的示例配置。

## 13. MVP 最终范围

为避免实现阶段继续扩张，第一版范围冻结如下：

### 13.1 必须实现

- 独立 Spring Boot 助手服务。
- YAML 项目注册。
- `POST /api/v1/diagnoses` 人工诊断接口。
- `POST /api/v1/events` 变更事件写入接口。
- Mock 日志、指标、慢 SQL 和发布事件。
- 本地文件日志适配器。
- JDBC 日志表适配器。
- 本地数据库分析适配器：只读查询数据库基础状态和慢 SQL 摘要。
- 脱敏、截断、去重、日志聚类和规则分析。
- Mock 模型适配器和 OpenAI API 模型适配器。
- 结构化 JSON 诊断报告。
- 两个通用演示案例。
- README、Dockerfile、Docker Compose 和 `.env.example`。

### 13.2 MVP 不实现

- Spring Boot Starter 的实际代码，仅冻结上报协议。
- Prometheus、Loki、Elasticsearch 和 OpenTelemetry 的正式适配器。
- Alertmanager 自动触发。
- Web 前端。
- 用户系统和复杂权限管理。
- 向量数据库和历史案例检索。
- 自动处置。
- 在服务端实现通用 ChatGPT OAuth 登录。

## 14. MVP 使用闭环

```text
注册 Java 项目
  → 配置本地日志文件、JDBC 日志表、本地数据库或 Mock 数据
  → 用户提交项目、时间范围和问题
  → 助手收集并标准化证据
  → 脱敏、截断、聚类和规则分析
  → Mock 模型或真实大模型生成结构化报告
  → 返回摘要、时间线、根因候选、证据和处理建议
```

第一版完成后，即使没有外部监控平台，也可以直接读取本地 Java 项目日志，并使用只读数据库账号分析数据库基础状态和慢 SQL 摘要。后续适配器只替换证据来源，不改变诊断主流程。

## 15. 本地联调必备能力

本地开发场景要求助手和被监控 Java 项目均可运行在同一台开发机上。第一版必须支持：

| 能力 | 数据来源 | 说明 |
| --- | --- | --- |
| 错误日志分析 | 本地日志文件 | 读取正在运行的 Java 项目日志，识别 `WARN`、`ERROR` 和异常堆栈 |
| 数据库日志表分析 | JDBC 只读查询 | 适用于项目将异常或操作日志写入数据库表的情况 |
| 数据库基础状态分析 | JDBC 只读查询 | 查询连接数、长事务或锁等待等基础信息 |
| 慢 SQL 分析 | 慢日志文件或数据库统计视图 | 统计参数化 SQL 模板、次数、平均耗时和最大耗时 |

### 15.1 本地数据库边界

- 第一版优先支持 MySQL 8.x 和 PostgreSQL 14+。
- 数据库账号必须只读。
- SQL 查询由代码内置，不允许用户或模型自由生成。
- 对不存在的统计扩展或权限不足场景，返回“数据源不可用”，不得导致诊断失败。
- 助手只输出排查建议，不自动执行 `EXPLAIN`、`KILL`、`CREATE INDEX` 或配置修改。

## 16. 大模型接入要求

第一版仅支持 OpenAI 相关接入方式。其他模型供应商留到后续迭代。

| 模式 | 场景 | 配置方式 | 是否适合线上独立部署 |
| --- | --- | --- | --- |
| `mock` | 开发、测试、无网络演示 | 无需凭据 | 是 |
| `openai-api` | 正式本地运行和线上部署 | 环境变量注入 API Key | 是 |
| `codex-cli` | 实验性本地运行 | 本机已有 `codex login` | 是（实验性） |

### 16.1 OpenAI API 模式

- API Key 通过环境变量注入，不写入配置文件和 Git 仓库。
- 支持配置 API Base URL、模型名、超时和最大重试次数。
- 线上独立部署默认使用该模式。

### 16.2 Codex CLI 实验性本地设计

- 该模式在 v0.1.0 中作为实验性本地 provider 提供。
- 该模式调用本机已安装的 `codex` CLI。
- 用户通过 Codex CLI 自身提供的登录流程完成 ChatGPT 账号登录。
- 助手不保存、不复制、不展示 Codex CLI 的账号令牌。
- 该模式只允许在本地开发环境启用。
- 官方没有明确说明个人 Codex 登录态可作为第三方通用排障后端自动化调用。使用者需要自行确认符合适用条款。
- 该模式默认禁用，不作为服务端通用 OAuth 方案。

### 16.3 明确边界

- 不在助手中自行实现 ChatGPT OAuth。
- 不支持将个人 Codex 登录状态复制到服务器或容器。
- 线上检测运行必须使用 API Key。
