# FaultPilot Java 故障排查与监控助手闭环自证

版本：V1.6
日期：2026-06-01

> 对应统一规格：`docs/specification.md` V1.6。

## 1. 结论

当前需求和开发设计已闭环，可以在评审通过后直接进入 MVP 开发。

项目不是完整监控平台。它以统一协议接收或查询可观测数据，通过确定性规则和大模型生成可解释的诊断报告。

## 2. 闭环检查

| 问题 | 已确认方案 |
| --- | --- |
| 谁使用系统 | 研发、运维、项目管理员 |
| 输入是什么 | 项目、环境、时间范围、问题；日志、指标、慢 SQL、变更事件 |
| 数据从哪里来 | Mock、本地文件、JDBC 日志表、本地数据库统计视图；后续 Prometheus、Loki、Elasticsearch、OpenTelemetry |
| 如何兼容不同 Java 项目 | 统一事件协议和适配器 SPI |
| 是否要求嵌入助手 | 否。助手独立部署 |
| Starter 是什么 | 可选轻量 SDK，仅异步上报脱敏事件 |
| AI 做什么 | 解释证据、生成根因候选和处理建议 |
| 规则做什么 | 限流、脱敏、聚类、统计和异常识别 |
| 输出是什么 | 摘要、时间线、根因候选、证据和建议 |
| 无大模型能否运行 | 能。Mock 模式和规则降级报告可运行 |
| 大模型如何接入 | MVP 正式支持 API Key；Codex CLI 仅保留实验性本地设计 |
| 无监控平台能否开发 | 能。本地文件、JDBC、本地数据库只读分析和 Mock 数据可运行 |
| 如何保证生产安全 | 只读账号、固定 SQL、时间范围、最大条数、脱敏和审计 |
| 第一版做什么 | 文档已冻结 MVP 范围 |
| 第一版不做什么 | Starter SDK、Prometheus、Loki、Trace、前端和自动处置 |
| 如何证明完成 | 开发方案中定义了验收条件和 Definition of Done |

## 3. 关键链路证明

### 3.1 本地开发链路

```text
本地 Java 日志文件或 Mock 数据
  → 助手适配器读取
  → 标准化、脱敏、聚类
  → 规则分析
  → Mock 模型或真实模型
  → 结构化报告
```

该链路不依赖 Fluent Bit、Loki、Prometheus 或 Starter。

### 3.2 旧项目接入链路

```text
数据库日志表
  → 只读视图和只读账号
  → JDBC 固定 SQL 查询
  → 标准日志事件
  → 诊断流程
```

该链路适用于只有数据库日志表的 Java 项目。

### 3.3 生产增强链路

```text
Java 项目
  → Prometheus、日志平台、慢 SQL、OpenTelemetry 或可选 Starter
  → 助手适配器
  → 同一套诊断流程
```

新增数据源只提高证据质量，不改变核心架构。

### 3.4 本地数据库分析链路

```text
本地 MySQL 或 PostgreSQL
  → 只读账号
  → 内置固定 SQL 查询统计视图
  → 连接状态、长事务、锁等待和慢 SQL 摘要
  → 脱敏和参数化
  → 诊断流程
```

该链路不执行模型生成 SQL，不执行写操作，不要求安装日志采集工具。

### 3.5 大模型接入链路

```text
正式本地运行或线上部署
  → OPENAI_API_KEY
  → OpenAI API

本地开发便利模式
  → 用户自行运行 codex login
  → 助手调用本机 codex exec
  → 不复制认证令牌
```

Codex CLI 登录模式不进入 MVP，不用于线上服务，不实现第三方 ChatGPT OAuth。使用者需自行确认符合适用条款。

## 4. 剩余非阻塞决策

以下事项不影响开始 MVP 开发，可以在实现阶段按默认值执行：

| 事项 | MVP 默认值 |
| --- | --- |
| GitHub 仓库名 | `faultpilot` |
| Java 包名 | `io.github.atomoty.faultpilot` |
| 开源协议 | Apache-2.0 |
| 默认数据库 | H2 |
| 默认模型 | Mock |
| 真实模型协议 | OpenAI API |
| 第一版 UI | 无，使用 REST API 和 README 命令演示 |

## 5. 评审建议

评审时重点确认三件事：

1. 第一版范围是否保持冻结，不提前实现第二阶段能力。
2. 是否接受先使用 REST API 演示，不开发前端。
3. GitHub 仓库名、Java 包名和开源协议是否需要调整。
